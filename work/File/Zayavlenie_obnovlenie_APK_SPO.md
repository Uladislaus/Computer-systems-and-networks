## Тема

О предоставлении (модернизации) автоматизированных рабочих мест сотрудников отдела разработки ПО в связи с несоответствием имеющейся техники задачам разработки и сопровождения программного обеспечения.

---

## 1. Общие основания

Сотрудники отдела разработки ПО выполняют работы по созданию, сопровождению и доработке прикладного программного обеспечения (в том числе на языках **Python**, **C#**, **JavaScript/TypeScript**), работе с **СУБД**, инструментами **Git**, средами **PyCharm**, **Visual Studio** / **Visual Studio Code**, офисными и специализированными пакетами (в т.ч. компоненты **ГИС Метео**, веб-стек **Django**, задачи по обработке данных).

Указанные задачи требуют одновременной работы нескольких ресурсоёмких приложений (IDE, локальные серверы разработки, браузер с документацией, средства виртуализации окружений, иногда — контейнеры и средства сборки). На имеющихся конфигурациях рабочих мест обеспечить **стабильную и безопасную** разработку **не представляется возможным**: наблюдаются длительные задержки, принудительное использование файла подкачки, сбои и закрытие приложений, невозможность открыть или полноценно использовать профессиональные IDE.

В целях выполнения должностных обязанностей и соблюдения сроков по поручениям руководства **просим** рассмотреть нижеперечисленные обращения и принять решение о выделении (закупке, замене, доукомплектации) технических средств.

### 2.3. Описание проблем в работе

На текущем компьютере при выполнении должностных обязанностей инженера-программиста регулярно возникают следующие ограничения:

1. **PyCharm** — проект открывается с длительной индексацией; при работе с репозиториями **Python/Django** IDE становится неотзывчивой; часто используется **100 % диска** (подкачка) и **>95 % ОЗУ**; полноценная отладка, анализ кода и одновременная работа с несколькими модулями **затруднены или невозможны**.

2. **Visual Studio / тяжёлые среды разработки** — запуск полнофункциональной конфигурации (решения с несколькими проектами, компоненты .NET, инструменты сборки) на данной конфигурации **не обеспечивает приемлемую производительность**; практическая работа сводится к минимальным сценариям или переносу задач на другие машины, что увеличивает сроки.

3. **Совмещение инструментов** — одновременное использование IDE, локального веб-сервера разработки, клиента **PostgreSQL**/иных СУБД, браузера с документацией и мессенджерами **превышает ресурсы 6 ГБ ОЗУ**; система вынужденно использует файл подкачки на медленном носителе, что **снижает производительность всего отдела** (длительное ожидание отклика на поручения).

4. **Двухядерный процессор** не соответствует типовым требованиям к рабочим станциям разработчиков (многопоточная сборка, фоновая индексация, линтеры, тесты), что **увеличивает время выполнения поручений** и создаёт риск срыва сроков по сопровождению ПО.

5. **Монитор** (при наличии ограничений по диагонали/разрешению/состоянию) — затрудняет работу с картой кода, diff, несколькими окнами; повышает утомляемость и число ошибок при ревью.

### 2.4. Обоснование необходимости новой техники (а не только ОЗУ)

Для должности инженера-программиста, выполняющего задачи полного цикла разработки, **узким местом является совокупность**: малый объём ОЗУ, устаревший двухядерный CPU и, при наличии, медленный HDD. **Добавление только ОЗУ** на платформе Pentium G2030 **не устраняет** ограничения по параллельным сборкам, индексации IDE и современным требованиям инструментов. **Замена системного блока** — экономически и технически обоснованный вариант для стабильной работы на **3–5 лет**.

**Минимально рекомендуемая конфигурация новой рабочей станции** (для согласования со службой связи и телекоммуникаций):

| Компонент | Рекомендация |
|---|---|
| Процессор | не ниже **4 физических ядер** (Intel Core i5 / AMD Ryzen 5 актуального поколения или эквивалент по регламенту закупок) |
| ОЗУ | **32 ГБ** (минимум **16 ГБ** при жёстком лимите бюджета) |
| Накопитель | **SSD NVMe/SATA ≥ 512 ГБ** (система + проекты + локальные БД) |
| ОС | Windows 10/11 Pro (64-bit), в составе лицензирования организации |
| Монитор | ≥ 24", 1920×1080, IPS или аналог по каталогу |

### 2.5. Влияние на работу подразделения

Без модернизации рабочего места сохраняются риски:

- невыполнения сроков по разработке и сопровождению ПО;
- невозможности использовать единый стандарт инструментов отдела (PyCharm/VS);
- повышенной нагрузки на коллег и серверные ресурсы за счёт переноса сборок;
- простоев по причине зависаний АРМ.

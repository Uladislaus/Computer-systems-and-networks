2. **§1 сжатое «о чём запись»** + таблица линеек (авиа / АРМ сервер+клиент).

4. **§3 два разных решения** — таблица «запись vs новость разработчика» (Москва/Токио 1.25° ≠ EGRR 0.5°). Не смешивать.
5. **§4–5 практический порядок** и где искать настройку (`GribModels.txt`, GribProc, `Grib.cdb`).
6. **§7 подтверждено / не подтверждено** сайтом.
7. **§8 анализ «Документов»** и книга «Анализ и прогноз…» — что искать Ctrl+F, чего в книге не будет.
8. **§9 фазы A (документы) → B (сервер)**.
9. **§10 дерево папки Work** — docs / notes / config.

Стиль Markdown (эталон оформления):

- заголовки `## N. …`, разделители `---`;
- таблицы для сравнений и чеклистов;
- **жирный** только для ключевых терминов (модель, путь, файл);
- блоки ```text``` для строк `GribModels.txt` и дерева папок;
- без «карточек» и лишней декорации — одна живая записка.

Дополнить из Obsidian-промпта spline (если на работе ещё нет):

- в **начале** `zapiska_*.md` — **журнал дат** (таблица: дата | тип | запись);

## 4. Чеклист ассистента на РАБОЧЕМ ПК (когда продолжите этот чат там)

Выполнить по порядку:

1. Открыть `D:\Work\GIS-Meteo-EGRR\` и перечислить файлы (`zapiska_*.md`, `Postanovka*`, `docs\`, `notes\`).
2. Сверить с эталоном `lr1/zapiska_grib_egrr.md` из git (ветка `cursor/transcribe-grib-briefing-f67c` или `main`, если влита).
3. **Diff по смыслу:** что есть только здесь → **добавить** на работу; что новее только на работе → **оставить**; конфликты — объединить, не затирая факты с сервера/аэропортов с работы.
4. Выровнять оформление шапки, таблицы «два решения», фазы A/B, дерево папок.
5. Добавить журнал дат, если отсутствует.
6. Obsidian:
   - vault = `D:\Work\` (или открыть, если уже так);
   - Settings → Files & Links → Automatically update internal links;
   - убедиться, что в дереве видны `GIS-Meteo-EGRR` и `Kubicheskiy-Splajn`.
7. Не трогать `Postanovka_zadachi_GRIB.txt` / сырую расшифровку как архив.
8. Кратко отчитаться: что добавлено, что оставлено с работы, что модернизировано в Obsidian.

**Не делать:** выдумывать, что уже «поменяли на сервере», пока нет фактов с рабочего контура; смешивать путь Москва/Токио 1.25° с официальным EGRR 0.5°.

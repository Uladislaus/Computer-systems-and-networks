# Piston Lab — карта

**Piston Lab** — личный учебный контур: азы языков и инструментов через маленькие **доведённые до рабочего вида** проекты («как поршень»); один смысл на разных языках для ассоциаций; отдельно — роли языков и их связка (экран → сервер → данные → позже телефон/движок); всё в Git/GitHub с двух устройств; карта в Obsidian + README в репо. Цель — один раз увидеть **целый контур** простого продукта и от него осознанно свернуть в веб, игры, данные или мобилки (а не сразу собирать chess.com).

## Паспорт

| Поле | Содержание |
| --- | --- |
| **Зачем** | Научиться сам; позже можно вырастить в обучение других. |
| **Как** | Мини-проекты «как поршень»: каждый шаг уже запускается. Правило: план → выполнение → итог. |
| **Три полосы** | 1) Сравнение языков (одна задача — несколько языков). 2) Роли языков (скрипт / сайт / API / позже мобилка / движок). 3) Связи (JSON, API, БД — не «алгоритм вызывает алгоритм»). |
| **Якорь продукта** | Сквозная тема **score / очки** — число-результат мини-действия (кликер, угадайка, позже игра), которое показывают и сохраняют. Не учебные баллы. |
| **Образ цели** | Понять устройство сложных вещей (мессенджер, chess.com, игра + модель), **не** клонировать их. |
| **Инструменты** | Git, GitHub, Git Bash/GUI; дома основа, на работе `pull` → маленький шаг → `push`. Python, C#, JS, Obsidian. |
| **Память** | Obsidian: план → выполнение → итог. README: что за продукт и как запустить. |
| **Результат базы** | Виден контур; развилка в любую сторону без ощущения «учил язык в вакууме». |

## Важно не перепутать

- **Bubble sort** — дорожка *сравнения языков*: один и тот же алгоритм в Python и C#, чтобы увидеть синтаксис, типы и стиль.
- **Score / очки** — сущность *мини-продукта*: игровой счёт (число), которое считают, показывают и сохраняют. Это **не** учебные баллы и не «очки за прохождение курса».

```text

├── README.md               # для людей на GitHub
├── python/
├── csharp/

├── api/                    # сервер + работа с БД
└── docs/                   # опционально: копия/ссылка на vault
```

Точная раскладка исходников может уточняться по ходу; смысл — разделить языки и слои, а обучение вести в vault.

## Правило работы

**План → выполнение → итог.**

1. Открыть заметку этапа в `01-План`.
2. Вести сессию по [[_Шаблон-выполнения]] в `02-Выполнение`.
3. Закрыть этап кратким [[_Шаблон-итога]] в `03-Итоги`.

Не смешивать «что собирались сделать» и «что получилось» в одной сырой заметке без структуры.
